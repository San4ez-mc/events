# Android: встановлення та публікація в Google Play

Застосунок: `apps/mobile` (Expo SDK 57). Бекенд має працювати на
`https://kiro.fineko.space` (див. `docs/DEPLOY.md`), бо збірка `eas.json`
вбудовує цю адресу. Поки бекенд не задеплоєно, застосунок не зможе увійти.

## A. Встановлення на свій телефон (APK, без магазину)

1. Створіть безкоштовний акаунт на https://expo.dev.
2. У терміналі:
   ```bash
   cd apps/mobile
   npx eas-cli login
   npx eas-cli build:configure      # один раз, погодьтесь на Android
   npx eas-cli build -p android --profile preview
   ```
3. Збірка займає 10-20 хв на серверах Expo. Наприкінці буде посилання та QR
   на `.apk`.
4. Відкрийте посилання на телефоні, завантажте APK. Android попросить дозволити
   встановлення з цього джерела (Налаштування -> Безпека). Встановіть.

Швидка перевірка без збірки: встановіть Expo Go, у `apps/mobile/.env`
поставте `EXPO_PUBLIC_API_URL` на IP комп'ютера (`http://192.168.x.x:3100`),
`pnpm --filter @kiro/mobile start` і відскануйте QR. Push-сповіщень у Expo Go на
Android немає.

## B. Публікація в Google Play

### Одноразова підготовка
1. Акаунт розробника Google Play: https://play.google.com/console, разова
   плата $25, підтвердження особи. Для нових особистих акаунтів Google вимагає
   закритого тестування: мінімум 12 тестувальників протягом 14 днів перед
   виходом у production.
2. Фінальний `applicationId`. Зараз `space.fineko.kiro` тимчасовий. Після першої
   публікації змінити його неможливо, тож вирішіть зараз і змініть в
   `apps/mobile/app.json` (`android.package`).
3. Матеріали: іконка 512x512 PNG, feature graphic 1024x500, мінімум 2
   скриншоти телефона, короткий (80 симв.) і повний опис, політика
   конфіденційності за публічним URL (обов'язково: застосунок збирає email
   і ім'я).
4. Push-сповіщення: у Firebase створіть проєкт, додайте Android-застосунок з
   тим самим `applicationId`, завантажте `google-services.json` і вкажіть його
   в `app.json` (`android.googleServicesFile`). Ключ FCM додайте в EAS:
   `npx eas-cli credentials`.

### Збірка та завантаження
```bash
cd apps/mobile
npx eas-cli build -p android --profile production   # створює .aab
npx eas-cli submit -p android --latest              # або завантажте .aab вручну
```
Для `submit` потрібен service account JSON з Google Play Console
(Налаштування -> API access), або завантажте `.aab` у розділ Release вручну.

### У Play Console
1. Створити застосунок (мова: українська, тип: застосунок, безкоштовний).
2. Заповнити: Store listing, Content rating (анкета), Target audience,
   Data safety (email, ім'я, ідентифікатор пристрою для push, поведінка в
   застосунку), Privacy policy URL, News/Ads декларації.
3. Testing -> Closed testing: завантажити `.aab`, додати тестувальників,
   утримувати 14 днів (для нових особистих акаунтів).
4. Production -> Create release -> завантажити `.aab` -> Send for review.
   Перевірка зазвичай від кількох годин до 7 днів.

## Перед публікацією перевірити
- Бекенд на `https://kiro.fineko.space` працює, реєстрація/вхід проходять.
- У мобільному наживо не пройдено: вхід, пошук, "Мої події", сповіщення,
  профіль, реєстрація на подію. Пройдіть їх на реальному пристрої з APK.
- Створення, редагування й керування подіями (реєстрації, статистика) тепер є і в додатку.

## Після першої збірки: Google-вхід і глибокі посилання
1. Відбитки ключа: `cd apps/mobile && npx eas-cli credentials` -> Android -> ваш профіль ->
   покажіть keystore: потрібні **SHA-1** і **SHA-256**.
2. Google Cloud Console -> Credentials -> OAuth client типу **Android** (package `space.fineko.kiro`) ->
   вставте **SHA-1**. Без цього вхід через Google в APK не працюватиме.
3. Глибокі посилання (відкриття `kiro.fineko.space/events/...` у додатку): на VPS у `apps/web` середовищі
   додайте `ANDROID_SHA256_CERTS=<SHA-256>` (кілька через кому) і перезапустіть `kiro-web`. Для Play-збірки
   додайте також SHA-256 із Play Console -> App integrity (App signing key).
4. Якщо міняєте `applicationId` - оновіть його в `app.json`, Google Cloud і тут.

## Правила для Android-збірок (рекомендації Play Console)

Play Console у розділі «Рекомендовані дії» тримає цей список. Нові збірки його не повинні погіршувати, тому:

1. **R8 / мінімізація коду.** У `apps/mobile/app.config.js` плагін `expo-build-properties` має ключі `enableMinifyInReleaseBuilds` і `enableShrinkResourcesInReleaseBuilds`. Назви змінюються між версіями Expo, а старий ключ ігнорується мовчки, тож після кожного оновлення Expo звіряти з `pluginConfig.d.ts` плагіна. Після змін у залежностях або keep-правилах перший реліз проходить закрите тестування: помилка R8 видна лише в роботі застосунку, не під час збірки.
2. **Орієнтація та розмір вікна.** В `app.config.js` `orientation` лишається `"default"`. Android 16 ігнорує блокування на великих екранах, і Play це позначає. Телефони тримаємо у вертикальному положенні кодом (`src/lib/phone-orientation.ts`), планшети й складні пристрої обертаються. Нові екрани не повинні припускати вертикальну орієнтацію: ніяких фіксованих висот і ширин у пікселях, лише гнучка розмітка.
3. **Безрамковий показ (edge-to-edge).** Не викликати у своєму коді `StatusBar.setBackgroundColor`, `setStatusBarColor`, `setNavigationBarColor`, не задавати `backgroundColor` для `StatusBar` і не покладатися на кольори системних панелей. Відступи робити через `react-native-safe-area-context`. Усе, що притиснуте до низу (поле введення, нижня панель, листи в `Modal`), мусить додавати `useSafeAreaInsets().bottom` до нижнього відступу, інакше кнопки навігації Android перекривають його. Решта застарілих викликів сидить у бібліотеках (React Native, react-native-screens, reanimated): їх прибирають оновленням залежностей, тож при кожному оновленні Expo SDK тягнемо свіжі версії.
4. **Розмір зображень.** Не додавати в застосунок картинки більші, ніж потрібно: у ресурси кладемо розмір під найбільшу щільність екрана, де вони показуються (іконка застосунку 1024 px лишається єдиним винятком). Фото подій завантажуємо з мережі, а не пакуємо в збірку. Нові PNG пропускати через стискання без втрат.
5. **Перед кожною збіркою для Play:** переглянути «Рекомендовані дії» і «Якість застосунку», виправити те, що стосується коду, а що ні (залежності) записати сюди з поясненням.
