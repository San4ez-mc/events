## 🔴 Критичне (блокує оплату/публікацію)

- 🟡 **WayForPay — "bad request" / "не вдалось розпочати оплату"** (і кредити, і підписка, і веб, і мобільний — це один спільний бекенд-баг): WayForPay вимагає **POST**-запит на `/pay`, а весь код (`WayForPayAdapter.createCheckout`, веб `window.location.href`, мобільний `Linking.openURL`) робить звичайний **GET**-редирект з параметрами в URL → WayForPay завжди відповідає "Bad Request — This page requires only POST data". Підтверджено відкриттям реального checkout-посилання в браузері. **Оплата через WayForPay ніколи фактично не працювала**, на жодній платформі. Виправляю: нова проміжна сторінка на нашому домені, яка робить справжній auto-submit POST до WayForPay.
- 🟡 **Подію не вдавалось опублікувати ("Перевірте правильність введених даних")** — знайдено корінь: бекенд вимагає `description` (опис) і `cityId` (місто) для публікації, але помилка на клієнті не показувала, яких саме полів бракує. Виправлено:
  - клієнт тепер парсить `details._` з відповіді бекенду і показує конкретний список полів, яких бракує (замість загального тексту)
  - "Назва" і "Опис" тепер позначені зірочкою * як обов'язкові в UI (раніше опис ніяк не виглядав обов'язковим, хоча публікація падала без нього)
  - "Місто" позначено зірочкою * теж
  - **Потрібно перевірити на новому білді**
- 🔴 **"Пошук адрес тимчасово недоступний"** — причина знайдена: Google Places API повертає **403 Forbidden** на запит з сервера (підтверджено в логах: `Places autocomplete HTTP 403`). Ключ `GOOGLE_MAPS_API_KEY` заданий на проді, але Google його відхиляє. **Потрібна дія в Google Cloud Console** (я не маю туди доступу):
  - переконатись, що "Places API (New)" увімкнено для проєкту, якому належить цей ключ
  - переконатись, що до проєкту підключений білінг-акаунт (Places API вимагає активний білінг навіть у межах безкоштовного ліміту)
  - перевірити обмеження ключа (API restrictions / HTTP referrer restrictions) — вони можуть блокувати виклики з сервера
- ❌ **Немає можливості додати свій район** — схоже, UI для цього вже є в коді (`addDistrict`), але користувач його не побачив/не знайшов — треба перевірити, чому

## Створення події — крок 2 (фото)

- ✅ Хрестик (кнопка видалення фото) тепер по центру — фікс `includeFontPadding`/`textAlignVertical` (Android-специфічна проблема рендеру іконок)
- 🟡 **Фото не завантажувалось ("щось пішло не так")** — знайдено й виправлено корінь проблеми:
  - nginx на сервері обмежував завантаження до 12MB, а застосунок дозволяє фото до 15MB і відео до 200MB → будь-яке реальне фото/відео відкидалось ще на рівні nginx (не JSON-відповідь → крашилась обробка помилки на клієнті)
  - nginx-ліміт піднято до 210MB на проді (вже задеплоєно, живе зараз)
  - `ApiRequestError` на клієнті захищено від краху на не-JSON відповіді (закомічено, чекає нового білда)
  - **Потрібно перевірити на новому білді**, що завантаження дійсно працює
- ⏳ **Фото в профілі (аватар) не завантажилось після кропу** — досліджую окремо, можливо той самий корінь (nginx), можливо інша причина
